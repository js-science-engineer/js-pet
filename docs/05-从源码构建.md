# 从源码构建

适用于想自己编译、修改，或需要 macOS 安装包的情况。

## 一、环境准备

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | 18 以上（开发用 22 已验证） | 官网安装包或 `brew install node` |
| npm | 随 Node 附带 | — |
| 网络 | 首次 `npm install` 需联网下载 Electron 二进制（约 100MB） | 见下方镜像配置 |

macOS 额外需要：`xcode-select --install`（Xcode Command Line Tools）。

## 二、获取源码并运行

```bash
git clone <本仓库地址>
cd js-pet
npm install
npm start
```

`npm start` 会直接启动开发版：宠物出现在桌面右下角，面板、托盘功能全部可用。

## 三、常用命令

```bash
npm test             # 运行单元测试（113 项，node:test，无需额外框架）
npm run smoke        # Electron 冒烟自检：启动宠物窗口+面板窗口，检查接口与安全隔离
npm run norm-look    # 归一化一张形象素材（开发用）
npm run build:win    # 打 Windows 安装包 + 绿色版
npm run build:mac    # 打 macOS dmg（必须在 Mac 上执行）
npm run build:all    # 同时打 win + mac（仅在 Mac 上有意义）
```

## 四、国内网络的镜像配置

Electron 与 electron-builder 的二进制默认从 GitHub 下载，国内会很慢甚至失败。构建时加环境变量：

```bash
# Windows（Git Bash / PowerShell 通用写法）
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install

# 打包时同样加上（NSIS 等工具链也走镜像）
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder --win
```

PowerShell 里等价写法：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npx electron-builder --win
```

## 五、构建 Windows 包

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run build:win
```

产物在 `dist/`：

| 文件 | 说明 |
|---|---|
| `js-pet-0.1.0-setup.exe` | NSIS 安装版（可选择安装目录、建快捷方式、可卸载） |
| `js-pet-0.1.0-portable.exe` | 绿色版单文件 |
| `win-unpacked/` | 免安装目录版，用于验证（可直接跑 `js-pet.exe`） |

**打包注意事项**

- 打包前先关掉正在运行的 js-pet，否则文件被占用会导致打包失败
  （症状：`doPack` 阶段报错。处理：`taskkill /F /IM js-pet.exe`，或任务管理器结束进程）
- 运行时用到的第三方库必须放在 `package.json` 的 `dependencies`，
  放 `devDependencies` 会被打包排除，运行时就会报 `Cannot find module`
- 打包白名单在 `electron-builder.yml` 的 `files` 段；不要手写排除 `node_modules`，
  electron-builder 会自动排除开发依赖
- 验证打包结果是否完整：

  ```bash
  npx asar list dist/win-unpacked/resources/app.asar | head -50   # 看是否缺文件
  JS_PET_SMOKE=1 ./dist/win-unpacked/js-pet.exe                    # 冒烟自检（结果写 smoke-result.json）
  ```

## 六、构建 macOS 包

> Windows 机器**无法**交叉编译 macOS 包（electron-builder 官方限制），必须在 Mac 上执行。

```bash
cd js-pet
npm install
npm run build:mac          # 同时产出 x64 与 arm64
# 只要本机架构：npx electron-builder --mac --arm64
```

产物：

| 文件 | 用途 |
|---|---|
| `js-pet-0.1.0-arm64.dmg` | Apple Silicon（M1/M2/M3/M4） |
| `js-pet-0.1.0-x64.dmg` | Intel Mac |
| `*.blockmap` | 差量更新用（当前未启用自动更新，可忽略） |

**已知差异**

- 图标：`build/icon.png` 为 256×256，`icon@2x.png` 为 512×512。
  若构建日志出现 `icon should be at least 512x512` 警告，把 `icon@2x.png` 复制覆盖
  `icon.png`（并同步改回 `.ico` 无关）后重新构建即可
- `mac.identity: null` 已在配置中关闭强制签名，没有证书也能构建成功
- 构建出的应用**未签名未公证**，用户首次打开需要放行，见 [macOS 安装指引](02-安装-macOS.md)

**如果想做签名与公证**（可选，需要 Apple 开发者账号 $99/年）：

```bash
export CSC_LINK=<.p12 证书路径>
export CSC_KEY_PASSWORD=<证书密码>
export APPLE_ID=<Apple ID>
export APPLE_APP_SPECIFIC_PASSWORD=<应用专用密码>
export APPLE_TEAM_ID=<团队 ID>
npx electron-builder --mac
```

并在 `electron-builder.yml` 的 `mac` 段补上 `identity` / `notarize: true` /
`hardenedRuntime: true` 等配置。

## 七、macOS 构建后的验收清单

- [ ] `npm run build:mac` 成功，`dist/` 出现 x64 与 arm64 两个 dmg
- [ ] 拖入"应用程序"后首次打开按指引放行成功
- [ ] 宠物窗口正常显示，拖动、右键菜单、托盘（菜单栏）都可用
- [ ] 退出后重新打开，设置与养成数据保留

## 八、修改形象素材

内置形象的绿幕原图在 `src/assets/builtin-looks/raw2/`，重新生成成品图：

```bash
# 单张
npm run norm-look -- src/assets/builtin-looks/raw2/front.png src/renderer/pet/looks/front.png
# 体检（检查残留背景、角色尺寸是否达标）
node tools/inspect-look.js src/renderer/pet/looks/*.png
# 重新生成应用图标（ico / png / @2x）
node tools/make-icons.js build/icon-src.png
```

归一化目标：画布 720×900，角色高 860px，底部对齐、水平居中 x=360。
抠图与去污逻辑在 `src/shared/keying.js`，**上传换装与构建工具用的是同一套代码**，
所以调这里能同时改善两边效果。
